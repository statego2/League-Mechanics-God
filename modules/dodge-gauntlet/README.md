# Dodge Gauntlet integration — work in progress

The player-facing entry point is the existing **Dodge Trial** in the repository root. Run `python3 -m http.server 8000` from the repository root and open `http://localhost:8000/`. Right-click moves, F flashes and T restarts. The prior standalone demo and its duplicate player simulation were removed. The implementation runs inside `game.js`'s existing 1/120-second update, map navigation, player, HUD, assets, projectile collision and renderer; no second game loop runs.

## Current implementation

The default Ahri-based Dodge Trial uses seeded regular spell selection, moving existing enemy actors, one encounter at a time, player-centered aim locked at cast, a 12-minute maximum and separate randomized ultimate clocks. Ezreal and Lux missiles use the existing swept relative-motion collision, with allied blockers and a two-contact limit for Lux. Ahri can hit once on each pass and homes to the caster on return; Vel'Koz creates two perpendicular missiles and shares one encounter outcome. Blitz has a first-target hook with an approximate pull. Xerath Q/W and rare Orianna/Malphite events have visible warnings, but are **training placeholders**, not complete champion implementations. The HUD shows hits/dodges; the results include per-spell qualified dodges and a provisional Flash count. Existing non-Ahri test profiles and other modes retain their previous behavior.

## Source and fidelity

Research PR #1 documents Blitzcrank Q (0.25 s cast, 1080 range, 140 width, 1800 speed) and Vel'Koz Q (0.25 s, 1100 range, 100/90 widths, 1300/2100 speeds). [Ezreal](https://wiki.leagueoflegends.com/en-us/Ezreal) lists 0.25 s, 1200 range, 120 width, 2000 speed, first target; [Lux](https://wiki.leagueoflegends.com/en-us/Lux) lists 0.25 s, 1300 range, 140 width, 1200 speed, two targets; [Ahri](https://wiki.leagueoflegends.com/en-us/Ahri) lists 0.25 s, 900 range, 200 width, 1550 outbound speed and one hit per pass. [Blitzcrank](https://wiki.leagueoflegends.com/en-us/Blitzcrank), [Vel'Koz](https://wiki.leagueoflegends.com/en-us/Vel%27Koz), and [Xerath](https://wiki.leagueoflegends.com/en-us/Xerath) provide community-reported details. Research was recorded against Data Dragon 16.21.1; mutable wiki pages do not prove patch-accurate historic values. The game converts distances and speeds by 0.5 canvas units per game unit.

## Remaining work before merge

- The director deliberately allows only **one encounter at a time**. It has no reachability solver, authored combination grammar, simultaneous pressure, adaptive difficulty or validated opportunity rate. It therefore does not meet the intended intensity or fairness criteria. The visible enemy is a generic existing actor and spawns at its entry point; visit/exit and cooldown rules are approximations.
- Xerath Q is a warned finite line and W a delayed circle, without complete timing/damage mechanics; Orianna's indicated ball is stationary and shockwave has no pull; Malphite is a warned circle without approach, dash or knock-up. Blitz pull is instantaneous with map clipping and lacks terminal collision and proper stun. Vel'Koz splits at a fixed travel fraction rather than a fully modeled recast; the split-on-hit/max-range and slow are incomplete. Ahri return speed is constant rather than accelerated. Damage is fixed post-mitigation training damage, not a full combat calculation. Walls do not block missiles. Some multi-target ordering within a single simulation step is approximate.
- Threat qualification uses existing stationary-position projection; delayed areas record whether the player entered the warning, which can overcount. Flash attribution is provisional and does not prove causation. Overlap survival is not measured. Host invulnerability and control effects are not yet a validated LoL ruleset. Existing results include per-ability counts but not blocked and unresolved breakdowns.
- No long-session browser gameplay or safety/cadence study has been completed. The draft PR is **not ready to merge** until the above mechanics, fairness, results and browser playtests are addressed.

Run `node --test tests/*.test.cjs` for tests against the actual game source. This branch intentionally modifies the existing game, rather than importing a separate simulation. For integration review, compare `game.js`, `index.html`, and tests against the target branch; avoid overwriting concurrent changes.
