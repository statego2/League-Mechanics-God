## 2. Coordinate and configuration contract

1. Keep existing simulation in canvas units for the first migration to avoid changing `world.js`, input and tests. Define `S=0.5` canvas units / game unit in one `simulationConfig` value; `toCanvas(x)=x*S`, `toWorld(x)=x/S`. Time is seconds, velocities game units/s before conversion, HP/AD unscaled. Label `S` as **A**, an arena calibration, not an official map projection. Convert numeric gameplay data once at config construction. Never scale seconds, attack speed, damage or HP. Eventually a true world-coordinate simulation can be a separate change.
2. A runtime adapter should consume `riot-roster.json` → `champions.Ahri.stats.{movespeed,attackrange,attackspeed,attackdamage}.value`; `featured.json` → `Ahri.attack_windup_percent.value`, `attack_missile_speed.value`, `q_*`; `minions/{stats,waves,behavior}.json` for supported values. Provenance stays alongside source data; adapter exposes numeric fields plus `sourceId`, `patch`, `confidence`, `approximationFlags`. Reject absent/null/conflicting required values in strict mode; opt-in scenario fallback must name and visibly flag its approximation. Do not interpret textual rules or historical Meraki as current machine values.
3. For `S=.5`, expected Ahri speed 165 canvas units/s, attack range 275 canvas units **before radii**, missile 875 canvas units/s, Q speed 775, Q width 100 canvas units / radius 50, Q cast .25 s and max outbound distance 450 canvas units. Champion gameplay radius 65 game units / 32.5 canvas units is a community snapshot; do not use the visual sprite's radius for it. Each entity needs distinct `gameplayRadius`, `pathingRadius`, `selectionShape`; use `d(centerA,centerB) <= attackRange + gameplayRadiusA + gameplayRadiusB` as the current edge-range implementation, subject to in-client confirmation per target type. Minion radius 24 canvas units in existing code is **A**, not verified.
4. A static site can continue to load without a server-side build: pre-generate a compact JavaScript module/constant from pinned data or preload JSON before enabling modes. File-protocol support is a current usability constraint: fetch may fail on `file://`; document the supported local server path and retain existing fallback defaults until migration is validated. Avoid runtime dependency on external Riot/CDN services. Detect schema/patch mismatch and show a safe fallback, not partially initialized combat.

## 3. Attack and damage contracts

**Attack state machine:** `READY → APPROACH → WINDUP → LAUNCH → RECOVERY → READY`. Persist order separately. Enter windup only when alive, target valid, in range, not casting/disabled and cooldown ready. On a replacement movement/stop command in windup, cancel; on launch create exactly one missile with `sourceId`, `targetId`, damage packet and launch timestamp; movement afterward cannot delete it. A dead/untargetable target before launch cancels per an explicit tested policy; target death after launch makes the homing shot resolve harmlessly, unless a later verified rule overrides. Move during recovery; do not allow another launch before ready. Do not claim LoL's release tolerance or attack buffering until verified.

Baseline `period=1/attackSpeed`; Ahri at 0.668 gives 1.497006 s. With normal modifier assumption, `windup=0.20/0.668 = 0.299401 s`, remainder ≈ 1.197605 s. Attack speed from **C** source is `baseAS + ASratio × bonusASFraction`; Ahri ratio 0.625 **R** and Q-style bonus fractions divide percent by 100. Growth, attack-speed caps and non-default windup modifiers require a separate verified profile; do not apply this windup expression to every champion. Scale output speed, not duration, to canvas. Projectile flight time `distance/speed` is only an estimate for a stationary target and center-path; homing target movement changes it.

Introduce `applyImpact({eventId, time, sourceId, sourceTeam, targetId, kind, raw, damageType, spellId})`. At impact check target validity, apply relevant pre-mitigation special effects, mitigation, then reduce HP once. For ordinary resistance `R >= 0`, `post = raw * 100/(100+R)`; current implementation also uses `2-100/(100-R)` for negative R, but that branch has **not** been independently verified here: retain as existing behavior labeled **A** until sourced. Physical uses armor; magic uses MR; true bypasses those resistances. Penetration, shields and special reductions are missing, so their order and amounts must not be invented. Use full precision internally and only round display. On-hit minion bonus in the collected source is physical and depends on target **current** HP at impact: melee +2%, caster +3.5%, siege +5%; record separately from base damage and apply appropriate mitigation. Verify type-specific interactions and ordering before claiming exactness.

Emit one `death({victimId, killerId, killerTeam, cause, time})` per victim and make all other handlers subscribe: player last hit/CS, allied/enemy/environmental miss, Ahri passive, gold and XP. Never infer credit from which UI function was called. For simultaneous impacts, use chronological impact time and deterministic stable event ID as an explicitly **A** tie-break; exact server ordering **?**. Resolve, mark dead once, suppress later impacts. Death-grace **C**: if a minion below 0.35% max HP takes lethal damage from another minion (damage ≤190), temporarily set HP 1 and schedule death 0.066s later unless another source damages it. Treat as opt-in until the exact predicate and interaction with shields are verified; never award a miss twice. HUD `missed` is drill-specific and should count only eligible enemy minions that die without player credit; finish-time survivors should be separately recorded as unresolved, not silently treated as actual deaths.

## 4. Minion and wave implementation

### Scheduling

Maintain a `matchTime` independent of drill elapsed time and a separate `nextWaveTime` + monotonic wave number. **R** first start 30s; start times 30, 60, 90… 810, 840, 865… 1765, 1790, 1810…; at 840 switch next interval to 25s, and at the first spawn after 1800 switch to 20s. Schedule from the prior nominal spawn, not `now`, and drain due events in a `while` loop so a long frame cannot skip waves. **C** units in wave spawn 0.792s apart, ordered super, melee, siege, caster. Process deterministic ordering per side/lane and maintain mirrored spawn offsets. Scheduler should generate events at exact timestamps; movement from nexus uses approximate lane geometry until actual map data is available. For an immediate CS drill use a declared `scenarioStart`/pre-positioned fixture with separate clock and clearly label its shortened travel, preserving existing 60-second playability.

**R/C:** ordinary wave has 3 melee + 3 caster; first siege wave is 3 at 90s, then every three waves before 14:00; every two after 14:00, every wave after 25:00. On siege waves at 14:00+ remove one melee; at 30:00+ remove one caster. Exact transition examples **C**: siege at 720, 810, 865, 915; 1465, 1515, 1540. Do not infer siege from an unreset global `waveNumber % n` at phase changes. Implement explicit phase state or a tested event table reproducing these boundaries; determine which wave gets a cannon from source-confirmed transition fixtures. Super replaces siege when inhibitor down; 1 per lane or 2 when all enemy inhibitors down **C**; inhibitor respawn cutoff and transition details **?**. Spawn health upgrades start 30s and repeat every 90s **C**; update stats at spawn using explicit verified formulas only. Full growth functions, speed buffs and unit spacing interactions **?**; keep null and use initial-only scenario until supplied.

### Entities and AI

Per minion: `id, team, lane, type, spawnWave, hp/maxHp, armor, mr, movementSpeed, gameplayRadius, pathingRadius, targetId, state, attackReadyAt, windupEnd, position, pendingEvents`. Begin `PATH` along scenario lane → `ACQUIRE` → `CHASE` → `WINDUP` → `LAUNCH` → `RECOVERY`, then re-evaluate target; when target dies or vision is lost reacquire, otherwise advance. Existing opposite-team entities in active checkout are a useful starting point. Remove same-wave-only targeting: enemies from different waves can interact. Implement candidate eligibility (alive, enemy, visible, in acquisition range; turret exceptions), then priority order **C**: enemy champion attacking allied champion; enemy minion attacking allied champion; enemy minion attacking allied minion; enemy turret attacking allied minion; closest enemy minion; closest enemy champion. General acquisition 500 game units; allied champion damage call-for-help range 1000 **C**, with exact origin/vision rules pending. Keep same-priority current target; switch for strictly higher priority when re-evaluation happens. Tie-break by distance then stable id is **A**. Re-evaluation interval **?**; expose a named approximation, do not pretend it is Riot timing.

Champion dealing damage to enemy champion with basic attack or most unit-targeted spells can trigger call-for-help **C**; spell-specific flags need validation. Attacking a minion no longer causes that aggro since 26.10 **C**. Turret-attacking minions generally ignore call-for-help, first-wave exception **C**. Do not apply this on Q merely because it damages a champion. Preserve first-wave behavior as a separable policy: mid ghosting 18s, side lanes 28s and distributed attacks on three opposing melees **C**; exact triggering requires in-client checks. `world.clip` handles static walls today, not dynamic collision; deterministic collision/avoidance against champions and minions is a separate approximate feature, with ghost flag disabling collision for the specified window. Do not repurpose gameplay radius as pathing radius.

Use `minions/stats.json` early HP melee 465, caster 284 **C**, and initial armor only when independently established. Siege 835 and super 1600 **C**; siege/super AD has explicit conflict, so it remains null. Base minion speed 350 **R** before modifiers/caps; existing 65 canvas/s = 130 game units/s and is an intentionally slower scenario, not calibrated. Existing .8s melee tick, .667 caster attack speed, 380 canvas/s projectile, ranges 103/323 and attack radii are **A** unless sourced; expose them as scenario config. Don't fabricate windup or launch speed: run opt-in experimental units with those present values tagged approximate. Launch caster missile at windup completion with `targetId`; at impact recompute current-health ratio, then dispatch common impact. Melee applies an impact at launch, not immediately on acquisition. Target death during windup, movement collisions and simultaneous lethal attacks have explicit deterministic tests; their exact in-game resolution remains **?**.

### Credit, XP and wave behavior

For unmodified base rewards, 26.1 **R**: melee 20 gold and 62 base XP; caster 31 base XP; siege/super 50 + 1 per upgrade gold and 75 base XP. Caster 14 gold **C**, lane modifiers must be confirmed. XP share coefficients by number of eligible champions are `[1, .65, .433, .325, .26, .217]` **R**, applied to base XP **per champion**, not to a shared total. **C** nearby eligibility 1500 game units and killer counts even if outside; individual rounding and exceptional credit need checking. CS count and last-hit gold derive from killer identity, while XP eligibility is a separate operation. Track each minion once. Jungle, denies, shared gold and queue variations are out of scope until sourced.

Slow/fast push, freeze, bounce and crash should emerge from different surviving units, arrival times, positions and turret interactions; a HUD label may classify observed state, but do not directly impose wave outcomes. There is no verified turret implementation: keep turret as a future entity sharing impact/death pipeline, with target priority, windup, period, projectile speed and switching marked unknown. Siege turret pre-mitigation max HP 14/11/8% for outer/inner/inhibitor and super 7% **C**; don't reduce HP by those percentages directly without subsequent mitigation and checking tower type. No tower-farming timing claim until the remaining fields are verified.

## 5. Spells, collisions and Ahri

Provide spell definitions separate from execution: `{castSeconds, rangeWorld, speedWorldPerSecond, widthWorld, collisionPolicy, maxHits, damagePacket, cc, phases, sourceId, confidence}`. Keep scripted supplemental telegraphs and difficulty modifiers clearly marked as training, never added to actual cast time. Straight skillshot event sequence: cast start → cast completion → launch at a documented origin → swept movement → earliest eligible collision → impact → stop/pierce according to policy → range expiry. Store actual traveled distance; don't start at an offset and then travel full nominal range without accounting for origin. Compute moving-circle contact using relative start/end segments (`segmentHitTime`) and `missileRadius + targetGameplayRadius`; sort by contact time, stable tie-break **A**. Distinguish tracking auto from interceptable skillshot. Test minions and champions on both teams, visibility/untargetable conditions, fast crossings and zero motion. If hit budget exhausted, stop; AoE and terminal area checks are explicit phases, not expanded linear width.

For Ahri Q, carry `phase=out|return`, separate hit ID set per phase; 0.25s cast, outbound 900 world units, 1550 units/s and width 200 **C**, 35 rank-1 magic outgoing and true returning **C**. Return seeks current Ahri position; the existing constant 1400 world units/s is **A** because source reports a variable 60–2600 without function. Do not substitute a linear speed formula. A target hit twice on one pass gets only one impact; a target can receive one on each pass. Keep cooldowns and W/E/R properties not validated in `featured.json` clearly flagged; E collision and charm duration need per-rank current validation. W targeting priorities, R dash speed/lockouts and exact Q return shape remain open; no current numbers from Meraki. In CS mode, enable Q only behind a separate selectable ability-practice profile after source attribution is implemented; preserve the auto-only profile and its existing local records.

Blitz Q **C** cast .25s, speed 1800, missile width 140, travel 1080 plus separate terminal check; first hit triggers pull/stun and caster lock. Its reported 1115 displayed range is not a simple bullet travel distance. Vel'Koz Q **C** cast .25s, initial speed 1300/width 100/range 1100, two opposite perpendicular split missiles speed 2100/width 90/range 1100, recast after .25s of flight, split over .25s; exact launch origin/collision ordering remains open. These are later adapters, not priorities over lane mechanics.
