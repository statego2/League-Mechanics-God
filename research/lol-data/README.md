# League mechanics research snapshot

Research-only material; no production code is changed. As of 2026-10-30, Riot's version endpoint returned **16.21.1**. This is a scoped, incomplete evidence set, not a verified game-client recreation. `champions/riot-roster.json` covers all 173 champions in that Data Dragon snapshot. `champions/featured.json`, `minions/`, `core/`, and `skillshots/abilities.json` contain explicitly sourced measurements and rules. Community wiki pages are live observations, not immutable patch archives: `patch: 16.21.1` means the observation was collected for that target patch, not independent in-client verification. `source_reported` is not corroborated. `source/` preserves the Riot input and a SHA-256 is in the roster.

`champions/historical/` preserves 12 named Meraki records including all ability descriptions, numerical strings and stat objects, as **historical, unverified** data. Their shared asset URL indicates 15.15.1; that is not proof every field is from that patch. In particular Ahri Q and Tristana Q are stale. Never silently merge these into the current config. Paths at the file level identify the original subtree; native nested fields retain their original names. The original whole Meraki download is not committed due to size, but its hash is recorded in every extracted file.

Run `python3 research/lol-data/scripts/import.py` to regenerate the roster from the committed input. To retrieve the same pinned Riot URL, add `--download-riot`. For a fresh **unversioned** Meraki export use `--meraki /tmp/meraki.json --download-meraki`, review timestamps and diffs and reclassify fields before use. This will overwrite the historical extracts, so preserve the prior snapshot if desired. Add a champion by adding its exact Meraki key to `NAMES`, re-running the importer and reviewing each ability against current patch changes. Changing patch requires updating `VERSION`, input filename and source URL, reviewing source diffs, and revalidating all manually sourced values.

Test with `python3 -m unittest discover -s research/lol-data/tests -v`. The schema describes individual measurement records; the standard-library tests check the same mandatory fields and constraints, all JSON readability, source checksum, roster equality, and selected boundaries. They do not prove game accuracy. See [SOURCES.md](SOURCES.md), [DATA_GAPS.md](DATA_GAPS.md), and [INTEGRATION_GUIDE.md](INTEGRATION_GUIDE.md).
